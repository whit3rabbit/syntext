# Context engine evaluation

Question sets with known supporting evidence, run end to end through
`ContextEngine::assemble`. A question counts as supported when **every**
passage its answer depends on reaches the prompt the model would see. For
a model with a 4K to 8K window that is the measure that matters: it can only
use what it was given.

```sh
cargo run -p syntext-context --release --example eval            # every built-in set, 4K and 8K
cargo run -p syntext-context --release --example eval -- multihop --failures
cargo run -p syntext-context --release --example eval -- --windows 2048,4096 --json out.json
cargo test -p syntext-context --test eval                         # the regression gate
```

## Sets

| Set | Questions | What it measures |
|---|---|---|
| `multihop` | 36 | Two- and three-hop questions over a fictional world of people and companies. Facts are spread over profiles, standalone notes, and filler, among lexical decoys. Generated by `gen_multihop.py` (fixed seed). |
| `paraphrase` | 24 | Questions worded without the answer's vocabulary ("How do I get my money back?" against "Refunds are issued within 45 days"), with decoy documents sharing the questions' surface words. |
| `code` | 26 | Questions about this repository's code and docs, with and without identifiers. The corpus is the checked-out tree (minus `context/eval/`), with a syntext index attached. |
| `recall` | 10 | A 68-turn conversation with facts at different depths; early turns no longer fit as verbatim history and must come back from memory. |
| `turbospark` | 10 | Questions about the TurboSpark app's Rust and Swift code. External: `--corpus turbospark=<checkout>`. Nothing from that repository is stored here. |
| HotpotQA | any | Real multi-hop questions, from a local file: `python3 context/eval/fetch_hotpot.py --limit 200 --out hotpot.json`, then `--hotpot hotpot.json --hotpot-limit 200`. Reported twice: `hotpot-distractor` (each question against its own 10 paragraphs) and `hotpot-pooled` (against all questions' paragraphs at once). The data is CC BY-SA 4.0 and is not vendored. |

## Metrics

| Column | Meaning |
|---|---|
| All supports in prompt | Questions whose every supporting passage reached the prompt, as evidence or (for `recall`) as verbatim history. The headline number. |
| Support recall | Supporting passages that reached the prompt, over all of them. |
| All retrieved | Questions whose supports were all among the retrieved passages before packing. A gap between this and the headline means packing (budget, floor, caps) dropped evidence that ranking found. |
| MRR | Mean reciprocal rank of the first supporting passage in retrieval. |
| Evidence tokens | Mean evidence tokens used. |
| p50 / p95 ms | `assemble` latency. |

## Results

Release build, 4-core Linux container, default options, built-in
`HeuristicCounter`. "Lexical" is the engine without an embedder; "bge-small"
adds semantic retrieval with
[bge-small-en-v1.5](https://huggingface.co/BAAI/bge-small-en-v1.5) through
`embed_server.py` on CPU (`--embed`).

| Set | Lexical 4K | Lexical 8K | bge-small 4K | bge-small 8K |
|---|---|---|---|---|
| multihop | 36 / 36 (100%) | 36 / 36 (100%) | 36 / 36 (100%) | 36 / 36 (100%) |
| paraphrase | 10 / 24 (42%) | 10 / 24 (42%) | 24 / 24 (100%) | 24 / 24 (100%) |
| code | 23 / 26 (88%) | 23 / 26 (88%) | 24 / 26 (92%) | 25 / 26 (96%) |
| recall | 10 / 10 (100%) | 10 / 10 (100%) | 10 / 10 (100%) | 10 / 10 (100%) |
| turbospark | 6 / 10 (60%) | 7 / 10 (70%) | not run | not run |
| HotpotQA distractor, first 200 dev questions | 176 / 200 (88%) | 176 / 200 (88%) | 190 / 200 (95%) | 190 / 200 (95%) |
| HotpotQA pooled, 2,000 paragraphs | 153 / 200 (76%) | 152 / 200 (76%) | 170 / 200 (85%) | 170 / 200 (85%) |

Before the multi-hop chain fixes this set prompted (commit 1b4e30a), the
same lexical runs gave 20 / 36 (56%) on `multihop`, 172 / 200 (86%) on
HotpotQA distractor, and 153 / 200 (76%) pooled. The relation classes were
tuned on `multihop`'s wording, so that set overstates the gain; HotpotQA is
the independent check.

`paraphrase` is the lexical engine's known weak spot: a question sharing no
words, identifiers, or entities with its answer finds nothing. Embeddings
close it and also lift `code` and HotpotQA; no set dropped. They cost time:
with the model in a Python subprocess on CPU, embedding each question adds
about 10 to 20 ms (p50 1.3 to 12.9 ms on `multihop`, 11 to 32 ms on `code`), and
embedding this repository (about 400 files) once took about 13 minutes. The
two `code` questions still missed at 4K ask about a mechanism in words its
code does not use; the support is not among the retrieved passages at all.

## Adding questions

A set file is JSON:

```json
{
  "name": "example",
  "description": "What it measures.",
  "corpus": {"kind": "notes", "docs": [{"id": "refunds", "title": "Refunds", "text": "..."}]},
  "questions": [
    {"id": "ex-01", "question": "...", "tags": ["no-overlap"],
     "supports": [{"doc": "note:refunds", "contains": "Refunds are issued within 45 days"}]}
  ]
}
```

- `corpus.kind` is `notes` (keys `note:<id>`), `repository` (this
  repository, keys `<label>:<path>`, optional `"syntext": true`), `external`
  (a directory given at run time), or `conversation` (`"turns"` recorded
  into memory first).
- A support is a document key and text that must appear in the evidence
  taken from it. A key ending in `:` matches any document with that prefix
  (`turn:` for conversation turns).
- Pick `contains` text that the answer actually needs, short enough not to
  be split by condensation.
- A new built-in set needs a floor in `context/tests/eval.rs`.
